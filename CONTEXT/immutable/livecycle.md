# Lifecycle тикета

DevOrc работает только с тикетами, находящимися в `Todo` инфраструктурного проекта.

## Получение тикета

При выборе следующей задачи DevOrc:

1. Находит тикет в колонке `Todo`.
2. Переводит тикет в `In Progress`.
3. Загружает контекст тикета:
   - описание тикета;
   - комментарии тикета;
   - связанный Wiki-контекст;
   - проектный контекст;
   - связанные Pull Request.
4. Восстанавливает рабочий контекст перед началом итерации.

## Контекст тикета

Тикет является основным контейнером контекста конкретной задачи.

В процессе работы в тикете необходимо сохранять информацию, которая требуется для понимания текущего состояния задачи.

В контексте тикета должны фиксироваться:

- цель задачи;
- текущий статус;
- принятые решения;
- результаты исследований;
- обнаруженные ограничения;
- вопросы и полученные ответы;
- важные изменения требований;
- ссылки на связанные PR;
- другая информация, необходимая для продолжения работы.

Контекст должен позволять следующей итерации продолжить работу без необходимости восстанавливать потерянные знания из предыдущего запуска агента.

## Итерации

Работа над тикетом может состоять из нескольких итераций.

Каждая итерация должна:

1. Восстановить контекст тикета.
2. Восстановить необходимый проектный контекст.
3. Выполнить очередную часть работы.
4. Сохранить полученные знания и решения в контексте тикета.
5. Обновить Wiki при изменении долговременного технического контекста.
6. Определить следующее состояние тикета.

Контекст не должен храниться только в памяти агента.

## Завершение задачи

Если задача полностью реализована:

1. Обновить контекст тикета.
2. Убедиться, что все необходимые изменения проверены.
3. Создать Pull Request в `dev`.
4. Добавить ссылку на Pull Request в тикет.
5. Перевести тикет в `Review`.

Тикет **не переводится автоматически из `Review` в другое состояние и не закрывается**.

Тикет остаётся в `Review` до завершения человеческого ревью.

## Clarification

Если для продолжения работы требуется решение или информация от пользователя:

1. Зафиксировать вопрос в тикете.
2. Сохранить текущий контекст и состояние работы.
3. Перевести тикет в `Clarification`.
4. Завершить текущую итерацию.

После получения ответа пользователя тикет может быть возвращён в `Todo` для следующей итерации.
